# Security Policy

## Project status

SparkCall `0.1.0` is an early, preproduction release. It may contain security defects and is not suitable for assuming production-grade security. There is no guaranteed response time, remediation timeline, or service-level agreement (SLA) for reports.

## Reporting a vulnerability

Please do not disclose credentials, tokens, personal data, call recordings, call metadata, conversation contents, or other private communications in a public issue, pull request, discussion, or commit.

Use GitHub's private vulnerability reporting or security advisory flow only if private reporting is enabled for this repository. Otherwise, use a private contact channel explicitly published by a maintainer; do not invent or infer an email address. If none is published, you may open an issue asking only for a private reporting method, without naming the vulnerability or including evidence, personal data, or exploit details. The maintainer is **BOOMDEE**.

When a private channel is available, include only the information needed to reproduce and assess the issue:

- A concise description and security impact.
- Affected version, commit, or deployment context.
- Reproduction steps or a minimal proof of concept.
- Relevant logs with secrets and private call data removed or replaced.
- Any suggested mitigation, if known.

Please allow the maintainer to assess the report before making details public. Do not test against systems or accounts that you do not own or have permission to use, and do not access, alter, or retain other users' data.

## Scope and expectations

Security reports are welcome for vulnerabilities in SparkCall code and its documented configuration. Third-party services, infrastructure, and dependencies may require reporting to their respective maintainers. Because this is an early/preproduction release, security fixes, release timing, and disclosure decisions are handled at the maintainer's discretion and are not guaranteed.
